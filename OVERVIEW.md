TODO keeps task lists in plain Markdown `TODO.md` files: one global list in `~/TODO.md` and one per project in `<project root>/TODO.md`, on the daemon machine.

The TODO screen (sidebar) shows Global and every project that has tasks, filtered by All, Global, or Projects, with overall progress. Add tasks from the field at the bottom; pick its target with the chips above it (Global by default, or any project — taskless projects stay selectable there, and their first add creates the list). The Explorer TODO tab shows the current workspace's project list with its add input, even when no `TODO.md` exists yet. When the current workspace's project has open tasks, a composer pill appears above the chat input; press it to check off open tasks or open the Explorer TODO tab. `/todo [task]` adds a task to the current workspace's project and opens that tab. Command Center has actions for both views.

Items are Markdown checkboxes (`- [ ] task`). Press the checkbox to check it off, press the task text to edit it in place, and use × to delete it. Completed tasks are collapsed under each list. Views refresh every couple of seconds.

Each row has a drag grip on the right: drag it to reorder the task inside its list, or drop it onto another project's list to move it there (the TODO screen shows every list; the Explorer tab reorders within its own). The moved task keeps its checked state and note. Dropping near a row's top or bottom edge inserts before or after it; dropping elsewhere on a list appends at the end.

Indented non-checkbox lines directly under a task are its note: press a task to expand its details panel and edit the note there. Notes are stored as plain text in the same `TODO.md` — note edits rewrite those indented lines, and deleting the task deletes them too.

A `TODO.md` file is created on the first add; checking off, editing, and deleting never create one. Edits keep the file's other lines and line endings intact. If a task changed on disk since the view last refreshed, checking it off, editing it, or deleting it is refused so the wrong task is never changed. The plugin reads and writes only these files. A workspace rooted at `~` uses the Global list; projects rooted at `~/.paseo` have no list.
